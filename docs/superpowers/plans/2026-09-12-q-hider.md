# Q-Hider Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a configurable Manifest V3 extension that safely hides selected distracting traQ UI categories and restores them immediately when disabled.

**Architecture:** Load build-free UMD/global modules in order: `core.js` validates versioned settings and custom selectors, `detector.js` marks only semantically recognized DOM, `app.js` owns Chrome storage and the bounded SPA observer, and `content.js` starts the app. Visibility is controlled by root data attributes and one static stylesheet, so disabling a setting is immediate and does not require reversing DOM deletions.

**Tech Stack:** Manifest V3, browser JavaScript and CSS, Chrome storage API, Node.js 18 `node:test`, `node:assert/strict`, and development-only `jsdom@26.1.0`.

## Global Constraints

- Run only on `https://q.trap.jp/*` with the `storage` permission.
- Do not call the traQ API, read credentials, remove traQ nodes, or modify traQ/traQ_S-UI.
- Keep runtime files build-free and free of third-party imports.
- All hide switches default to false.
- Never use a complete generated CSS-module hash; a source-name prefix is only one signal and message/stamp/sidebar classification requires another semantic signal.
- Invalid custom selector lines prevent saving and identify the exact one-based line number.
- Settings changes must affect an already-open traQ page without reload.
- Mutation work must be debounced, idempotent, and bounded to added or nearby subtrees.
- Use test-first red-green-refactor cycles for every new behavior.

## File map

- `manifest.json`: Manifest V3 metadata, storage permission, options, and ordered content scripts.
- `package.json`, `package-lock.json`: tests, syntax checks, and jsdom development dependency.
- `core.js`: UMD/global settings defaults, normalization, root-attribute mapping, and custom-selector parsing.
- `core.test.js`: pure settings and selector tests.
- `detector.js`: UMD/global semantic detectors and marker application.
- `detector.test.js`: positive and negative traQ-like jsdom fixtures.
- `app.js`: UMD/global storage adapter, style/root state controller, observer queue, and lifecycle.
- `app.test.js`: fake-Chrome and jsdom integration tests.
- `content.js`: guarded startup only.
- `content.css`: root-state-driven hide/layout rules.
- `options.html`, `options.css`, `options.js`: switches, custom selectors, bulk actions, and status.
- `options.test.js`: options interaction and validation tests.
- `manifest.test.js`: permissions and entry-point checks.
- `README.md`: installation, behavior, privacy, limitations, and tests.

- [ ] **Step 3: Implement settings storage and root state**

Storage contract:

```js

  load(),
  save(settings),
  subscribe(listener)
}
```

Normalize all reads. A storage rejection returns all-off session state and logs
one `Q-Hider:` warning. `subscribe` responds only to the documented key in the
`sync` area and returns an unsubscribe function.

- [ ] **Step 4: Write failing stylesheet contract tests**

Read `content.css` as text and assert each root state gates its matching marker,

elements and pseudo-elements, and no selector contains a complete hash-shaped
class token.

- [ ] **Step 5: Implement scoped hide and layout CSS**

Use selectors shaped like:

```css
html[data-q-hider-hide-stamps='true'] [data-q-hider-stamps],
html[data-q-hider-hide-viewers='true'] [data-q-hider-viewers] {
  display: none !important;
}
```

Provide separate rules for all markers. Author mode hides marked author nodes
and changes only `[data-q-hider-author-layout]` to reclaim the author column.
Stamp/attachment margins collapse only under their corresponding root state.
Animation mode uses `animation-duration: 0.001ms !important`,
`animation-iteration-count: 1 !important`, `transition-duration: 0.001ms
!important`, and `scroll-behavior: auto !important` rather than pausing
animations in an indeterminate visual state.

- [ ] **Step 6: Write failing lifecycle and observer tests**

With a fake MutationObserver and controlled scheduler, assert:

- `start()` loads settings, scans once, and subscribes once;
- five mutation callbacks before the timer runs produce one reconciliation;
- only added elements and their bounded nearby ancestors are passed to scan;
- a settings update applies root state and rescans for newly enabled custom
  selectors;
- rescanning is idempotent;
- `stop()` disconnects, unsubscribes, cancels pending work, and clears Q-Hider
  root attributes without removing traQ elements.

- [ ] **Step 7: Implement the bounded app controller**

Keep a Set of pending scan roots and collapse descendants when an ancestor is
already queued. Default debounce is 50 ms. Log each runtime-invalid custom
selector once per app lifetime. Do not observe extension option pages.

```js
    chromeApi: chrome

  console.error('Q-Hider: 起動に失敗しました', error)
}
```
